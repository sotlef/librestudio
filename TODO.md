## Code-приложение (sfx2::sidebar reuse)

- **`SolutionDeck`/`SolutionPanel`/`OutputDeck`/`OutputPanel` не scoped к
  "Code"** — все четыре зарегистрированы в `officecfg/.../Sidebar.xcu` с
  `ContextList = "any, any, visible"`, хотя по смыслу нужны только "Code".
  Причина: `ResourceManager::ReadContextList` резолвит поле Application
  только через закрытый, нерасширяемый enum `vcl::EnumContext::Application`
  (Writer/Calc/Draw/Impress/... + "any"/"none") — произвольное имя вроде
  `com.sun.star.code.CodeDocument` там не распознаётся и запись тихо
  отбрасывается (`SAL_WARN` + `continue`), из-за чего панель вообще
  перестаёт матчиться (воспроизведено и исправлено для Output 2026-10-01).
  Следствие: эти 4 деки/панели потенциально показываются и в реальном
  левом/правом Sidebar ЛЮБОГО другого приложения (Writer/Calc/Impress/...),
  не только "Code" — непроверено, т.к. другие приложения в эту сессию не
  запускались. `PropertyDeck`-в-Code и `OutputDeck`-в-левом-Sidebar-Code уже
  пришлось прятать через `SidebarController::RegisterHiddenDeckForApplication()`
  (`code/source/codeapp.cxx`) — тот же трюк пришлось бы повторять для каждого
  другого приложения, если там тоже окажется нежелательная лишняя вкладка.
  Настоящее решение — расширить `vcl::EnumContext::Application` отдельным
  значением для "Code" (инвазивно: enum используется во множестве switch'ей
  по всему дереву, не проверено на исчерпываемость) — сознательно отложено.
  **Требование к решению:** все панели должны быть по-настоящему scoped —
  при добавлении новой панели в нижний Output-док не должно требоваться
  отдельно заботиться, чтобы она не появилась в левом Sidebar (и наоборот).
  Сегодня это обеспечивается вручную, точечным вызовом
  `RegisterHiddenDeckForApplication()` на каждую новую деку — это именно тот
  ручной шаг, который должен стать не нужен.

- **`OutputController`'s "..." popup-меню — no-op.** TabBar у Output-дока
  получает пустой `PopupMenuSignalConnectFunction` (`[](weld::Menu&,
  weld::Menu&) {}`) — кнопка меню есть, но пункты Dock/Undock/Customization
  ничего не делают. Нормально для единственной вкладки v1, станет заметно
  при добавлении второй панели в Output.

- **Output-док нельзя свернуть до одной полоски вкладок** — в отличие от
  реального Sidebar (клик по активной вкладке/грипу прячет деку, оставляя
  только TabBar), `OutputController` всегда показывает деку открытой; нет
  аналога `SidebarController::RequestCloseDeck()`/`OpenThenToggleDeck()`.

- **`TabBar`'s вертикальная раскладка в горизонтальном bottom-доке.**
  `sfx2/uiconfig/ui/tabbarcontents.ui` жёстко верстает колонку иконок
  (`GtkToolbar orientation="vertical"`), рассчитанную на левый/правый
  Sidebar. В Output-доке (широкий и невысокий) та же раскладка просто
  прижата к левому краю — с одной вкладкой незаметно, при нескольких
  вкладках будет смотреться не как у Visual Studio (там вкладки в ряд).

- **Небольшой отступ справа у нижней Output-панели не объяснён.** Остался
  после волны 2026-10-02 (симметрия TabBar-кнопок + перенос линии
  сплиттера к краю контента + `LayoutSize(0,-1,-1)` для жадных панелей).
  Проверено и исключено заливкой цветом: это НЕ область сплит-окна (синяя
  заливка не проступала) и не резерв под скроллбар деки (после
  `LayoutSize(0,-1,-1)` дека свой скроллбар не включает). Что-то внутри
  самой деки/панели правее лога, порядка нескольких пикселей. Пользователь
  явно согласился оставить как есть ("ладно, давай так оставим").

- **Grip-click / "панель пропадает при клике по сплиттеру" баг Sidebar** —
  не решён, расследование явно остановлено пользователем в этой же сессии
  до появления Output-дока. См. `codeviewshell.cxx`'s `LayoutPanels()`
  получает `rOfs=0,0` во время fade-переходов — причина не найдена.

- **Qt6/KDE HiDPI рендеринг хуже gtk3** — `vclplug_qt6` собирается чисто под
  Qt 6.10.3, но шрифты/UI выглядят хуже gtk3 под KDE HiDPI. Пользователь
  явно отложил разбор на будущее (см. память `project_qt6_hidpi_rendering`).
  Частично разобрано 2026-10-01: главный виновник размеров найден и
  исправлен — апстримный хардкод `HighDpiScaleFactorRoundingPolicy::Round`
  в `QtInstance.cxx` (tdf#159915) превращал системные 1.5 в DPR=2 и
  раздувал весь Qt-хром на ~33% против родных KDE-приложений; форк
  вернулся к Qt6-дефолту PassThrough. Размеры подтверждены пользователем.

- **Qt6 + PassThrough (дробный DPR 1.5): проблемы с перерисовкой** —
  после перехода на PassThrough пользователь видит артефакты перерисовки
  (детали не уточнялись, разбор явно отложен — «вернемся чуть позже»).
  Это ровно тот класс дробно-DPR багов округления в `QtFrame`/`QtGraphics`,
  из-за которых апстрим и захардкодил Round (tdf#159915: обрезанный About
  при 150%). Чинить надо сами баги координатной математики, а не
  возвращать Round.

- **Error List: лупа не внутри поля поиска, а перед ним** — в Visual
  Studio иконка поиска нарисована ВНУТРИ строки ввода, перед стрелкой
  выпадающего списка. У `weld::ComboBox` нет API для entry-иконок
  (gtk3-weld вообще пересобирает editable-комбобокс из собственного
  шаблона `vcl/ui/combobox.ui`, выбрасывая исходный `GtkEntry` вместе с
  его `primary-icon-name`), поэтому в `errorlistpanel.ui` лупа пока
  стоит отдельной `GtkImage` вплотную слева от комбобокса. Честное
  решение — новый weld-API (`set_entry_icon_name()` или подобный) с
  реализацией во всех трёх бэкендах + слот под иконку в шаблоне.

- **Error List: у колонки Severity нет всплывающей подсказки на
  заголовке** — VS показывает «Severity» только в tooltip'е пустого
  заголовка колонки с иконками. У `weld::TreeView` нет API подсказок на
  заголовках колонок (и generic-путь через `SvHeaderTabListBox` его
  тоже не прокидывает) — заголовок пока просто пустой.

- **Find in Files (диалог, `code/source/finddialog.cxx`): «Current selection» / «Current block» не работают** — переключатели видны при области Current document, но поиск (`FindOptions`) выделения не знает, Find Next / Replace Next / Replace All всегда идут по всему документу. Нужно поле диапазона в `FindOptions` и чтение выделения из редактора через `XEditorHost`.

- **Find in Files: одно совпадение на строку** — `FindResult` хранит только первое совпадение строки (`searchFile` в `services/finder.cxx`), поэтому Find Next / Previous пропускают остальные совпадения в той же строке, а Replace Next доходит до них лишь повторным поиском после замены. Replace All заменяет все совпадения в найденных строках.

- **Find Next не начинает с позиции курсора** — обход идёт с первого совпадения в порядке файлов, а не от каретки редактора.

- **Replace Next не раскрывает группы regex** — замена вставляется как есть (`$1` остаётся текстом), тогда как Replace All раскрывает их через ICU `appendReplacement`; результаты двух кнопок расходятся.

- **Многострочные совпадения не находятся** — поиск идёт построчно; шаблон с переводом строки ничего не найдёт. Preserve case тоже работает только для совпадений в одной строке.

- **Current document без открытых документов не предупреждает** — `DocumentUrl` пустой, поиск молча ничего не находит.

- **Диалог поиска модальный** — блокирует редактор, пока открыт; Find Next нельзя нажимать, правя документ (в Visual Studio диалог немодальный).

- **Нет горячих клавиш F3 / Shift+F3** для Find Next / Previous без диалога.

- **Replace All без подтверждения и итога** — нет вопроса перед заменой и сообщения «заменено N вхождений в M файлах»; изменённые документы остаются несохранёнными.

- **Find in Files, панель: фильтр Current Document не следует за сменой вкладки редактора** — нет уведомления о смене активной вкладки, таблица обновляется только при событиях менеджера документов или смене пункта комбобокса.

## Индекс символов (`theSymbolIndex`, v1: индекс + F12 + Ctrl+T)

- **Нет автодополнения.** Нужен `clang_codeCompleteAt` (или LSP) и popup в `CodeEditView`; хука «каретка/текст изменились» у редактора нет.
- **Нет find-references.** Вхождения (использования) при индексации не сохраняются, в `Symbol` их нет. Хранить надо при разборе, а не искать grep'ом.
- **Хранилище только в памяти.** `XSymbolStore` — интерфейс, реализация `symbolstore.cxx` (шард на файл, линейный поиск по имени). Нужна вторая реализация на диске (SQLite или шарды, ключ — хэш содержимого + хэш флагов), иначе каждое открытие решения индексирует всё заново.
- **Правка заголовка не переиндексирует зависимые файлы.** Индексируется только изменённый файл; `.cpp`, включающие этот заголовок, остаются как были. Нужен граф включений.
- **Символы только верхнего уровня областей видимости.** Индекс идёт с `SkipFunctionBodies`, поэтому локальные переменные и параметры не входят (так задумано), но и лямбды/локальные классы внутри функций тоже.
- **Нет отдельного признака forward declaration.** `Symbol.IsDefinition` различает определение и «не определение»; `class Foo;` и объявление метода в заголовке для базы одно и то же. F12 с `class Foo;` ведёт к остальным объявлениям, а не к определению класса.
- **«Курсор на записи» сравнивает URL строго.** Если провайдер (путь libclang) и проект дают разные URL одного файла (символьная ссылка, `..`), F12 может показать диалог выбора вместо прямого перехода.
- **Без `compile_commands.json` заголовки разбираются с флагами по умолчанию** (C++20, без include-путей); тип языка для `.h` угадывается по `-std=` из флагов. Фолбэка на CMake file API нет.
- **Только C и C++.** Провайдеры для других языков регистрируются по MIME-типу в `theSymbolIndex::registerProvider`, но ни одного, кроме libclang, нет.
- **Событие правки документа не несёт диапазона** (`DocumentEvent` — только URL), поэтому индекс каждый раз перечитывает весь текст; настоящей инкрементальности нет.
- **Горячие клавиши зависят от конфигурации акселераторов.** Копирование/вставка/отмена теперь идут слотами (`SID_COPY` и др.) по `Accelerators.xcu`; клавиша без привязки не делает ничего (вставка символа для Ctrl-комбинаций исключена). Схем клавиш (VS, IntelliJ…) и их переключения ещё нет; состояние пунктов Edit (доступно/нет) не реализовано — всегда включены.

## Версионирование (`theVcsManager`, v1: Git, виджет ветки + попап веток)

Не собрано и не проверено в работе: код написан по плану, сборку и запуск делает пользователь.

- **Только ветки и Fetch/Pull/Push.** Нет merge, rebase, delete, rename, compare, track; нет лога коммитов, diff, blame, stash. Общий интерфейс (`XRepository`, `XBranchBrowser`) намеренно мал; всё, что меняет состояние, живёт в интерфейсе системы (`git/XGitRepository`).
- **Нет статуса файлов.** В дереве решения нет цветов/значков изменённых файлов, в редакторе нет gutter-индикаторов.
- **Аутентификация не поддержана.** Git запускается с `GIT_TERMINAL_PROMPT=0`: fetch/pull/push, которым нужен пароль или passphrase, падают с сообщением git'а. Нужен askpass-посредник с диалогом.
- **Только git CLI.** Нет libgit2-реализации; каждый запрос — отдельный процесс (быстрый запрос ограничен 20 с). Вторая реализация `XVcsProvider` для того же `Kind` ничего не потребует менять выше.
- **Слежение поллингом.** Раз в 2 с смотрятся mtime `HEAD`, `packed-refs` и `refs/heads|remotes`; нужен inotify/ReadDirectoryChanges. Изменение без смены этих файлов (rebase в процессе, смена upstream в config) не видно до следующей операции.
- **Один репозиторий в виджете.** Показывается репозиторий активного проекта, иначе первый из открытых; для решения из нескольких репозиториев/submodule нужен выбор (по активному документу).
- **Нет других систем.** SVN/Hg/Perforce — отдельные `XVcsProvider`; для SVN `XBranchBrowser` не подходит (ветки — копии путей), нужен свой интерфейс и свой попап (`VcsStatusBarControl::Click` выбирает попап по `Kind`, сейчас только `git`).
- **Попап не проверен на обоих бэкендах.** Положение при открытии у правого нижнего края (разворот вверх/влево делают сами бэкенды), размер generic-vcl-попапа, Up/Down из поля поиска.
- **Нет переименования/удаления ветки из контекстного меню**, нет «Checkout and rebase», «Compare», «Show diff with working tree» (то, что есть у CLion).

## Git Changes (панель `GitChangesPanel`, `XGitWorkingCopy`)

Собрано, но не проверено в работе: форму и операции проверяет пользователь.

- **Нет просмотра diff** и построчного stage; двойной клик по файлу только открывает его.
- **Нет истории коммитов**; amend берёт сообщение из поля (пустое поле оставляет прежнее), само сообщение последнего коммита в поле не подставляется.
- **Рабочее дерево не отслеживается.** Список обновляется по событию репозитория (HEAD, refs, index), по сохранению и закрытию документа и по Refresh; правка файла другой программой или `git` без изменения index не видна до следующего повода. Нужен inotify.
- **Конфликты не разрешаются.** Файл в конфликте показывается с `!`, дальше только вручную.
- **Rollback неотслеживаемых** удаляет файлы (`git clean -f` по явным путям, каталоги не трогает); подтверждение одно на всю выборку, корзины нет.
- **Хуки и подпись.** pre-commit, которому нужен ввод, и gpg с запросом пароля падают: stdin закрыт, `GIT_TERMINAL_PROMPT=0`.
- **Stash целиком или с неотслеживаемыми**; отдельных файлов нет, сообщение stash не вводится (берётся git'ом).
- **Один репозиторий.** Панель показывает репозиторий активного проекта, иначе первый открытый.
- **Нет значков статуса в Solution Explorer и в редакторе.**
- **Выбор нескольких строк** пока не поддержан: контекстное меню и чекбокс работают с одним файлом или целой группой.
- **Gtk-CRITICAL при показе деки Git Changes (причина не найдена).** На gtk3 при открытии деки в консоль идут `gtk_widget_realize: assertion 'widget->priv->anchored || GTK_IS_INVISIBLE (widget)' failed` и `gdk_window_set_cursor: assertion 'GDK_IS_WINDOW (window)' failed`. Так отвечает `GtkInstanceDrawingArea::set_cursor` (vcl/unx/gtk3/gtkinst.cxx), когда его зовут до того, как виджет попал в окно. В панели drawing area нет; в коде Code это либо зоны растягивания popup веток (`gitbranchespopover.cxx`: курсоры теперь ставятся в `Show()`, правка не собрана и не проверена), либо `CodeEditView::SetDrawingArea`. Если сообщение останется, снять стек: запуск `code` под gdb с `G_DEBUG=fatal-criticals`.

## weld::MDI (новый виджет документных вкладок с крестиком/булавкой)

- **Реализован только для gtk3 и Qt.** Generic/headless бэкенд
  (`SalInstanceBuilder::weld_mdi()`) — заглушка, возвращает `nullptr`.
  Нативной реализации под macOS/Windows/iOS/Android нет вообще (эти
  бэкенды в этом форке, там где вообще существуют, никогда не проверялись
  на паритет с `weld::Notebook`, тем более с `weld::MDI`). Любой запуск
  "Code" не под `SAL_USE_VCLPLUGIN=gtk3`/`qt6` получит `nullptr` вместо
  виджета.
- **Опции отображения не реализованы, добавятся отдельными итерациями**
  (по плану by design, не забытое): расположение полосы вкладок
  (сверху/снизу/слева/справа), несколько рядов вкладок вместо скролла,
  видимость кнопки pin и т.п. — `insert_document()` и остальной v1 API
  сознательно не угадывают их форму заранее.

## Непортированные подсистемы

- **Словари (`dictionaries`) не портированы — проверка орфографии не
  работает ни для одного языка.** Апстримный сабмодуль `dictionaries`
  (hunspell-словари + hyphenation + thesaurus, каждый язык упаковывается
  собственным `Dictionary_*.mk` как bundled-расширение) в CMake-порте
  отсутствует целиком; в `instdir/share/` нет ни одного `.dic`/`.aff`.
  Видимый симптом: Options → Languages and Locales → General, списки
  «Default Languages for Documents» — у каждого языка зарезервирована
  колонка под иконку «ABC✓» (`svx/source/dialog/langbox.cxx`,
  `m_bWithCheckmark`: `lngcheck` для языков со спеллчекером, прозрачный
  `notcheck.png` для остальных), но так как словарей нет, ВСЕ строки
  получают прозрачную заглушку — выглядит как беспричинный отступ в
  тексте (расследовано 2026-10-02: сама цепочка иконок исправна — zip
  содержит и `notcheck.png`, и `links.txt` с резолвом
  `lngcheck → cmd/sc_spelling.png`; не хватает только данных). Объём
  порта нетривиален: это не один таргет, а генератор per-словарных
  расширений поверх непортированной Extension_*.mk-подсистемы (тот же
  пробел уже помечен у `rust_uno`'s `.oxt`-упаковки).

## Как пользоваться этим файлом

- Один пункт = один конкретный, проверяемый долг (не "сделать получше").
- Явно пишите, ЧТО сломано/недоделано и ПОЧЕМУ (причина, не только симптом) —
  чтобы можно было начать чинить без повторного расследования с нуля.
- Закрыли пункт — удалите его отсюда (git history и так сохранит).
